## Decisões de design

1. **RLS (Parte 6):** migração nova `0002_row_level_security` (0001 intocada — publicada na main). Papel `cifra_app` (login, senho `cifra`), papel `cifra_auth_lookup` (NOLOGIN) para lookups de autenticação; API conecta como `cifra_app`. RLS + FORCE RLS em `users`, `refresh_tokens`, `backup_codes`, `audit_events`. Contexto: GUC por transação `app.auth_scope` = `'user'` (com `app.current_user_id`) ou `'auth'`. Policies: `auth` → INSERT/SELECT limitado a users (por e-mail) e refresh_tokens (por jti_hash); `user` → CRUD total das linhas próprias. `set_config(..., true)` garante zero vazamento pelo pool. Migrações/Alembic seguem no papel owner `cifra` (superusuário do banco dev), fora do FORCE.
2. **Audit (Parte 5):** service central `app/services/audit.py` com `AuditEventType` (StrEnum) e `record_audit_event(session, ...)`. Sanitização recursiva de before/after (denylist de chaves sensíveis). Append-only no BANCO: triggers `BEFORE UPDATE OR DELETE → RAISE EXCEPTION` em `audit_events` (migração 0002). Eventos críticos commitados dentro da transação do caso de uso. Falha de escrita de evento não-sensível (rate limit) não derruba a resposta; eventos de sessão/2FA são transacionais.
3. **Rate limit (Parte 3):** `app/core/ratelimit.py` com scripts Lua atômicos (INCR+EXPIRE em transação Redis), janela fixa por minuto. Chaves: `cifra:rl:login|register:<identity>` e `cifra:rl:global:<ip>`. Resposta 429 com `Retry-After`. Redis indisponível: política fail-open explícita e documentada para rate limit (disponibilidade do login), com AuditEvent; lockout permanece fail-closed independente. Health fora do limite global.
4. **IP/proxy (Parte 3):** `client_ip(request)`: por padrão peer direto; headers só com `TRUST_PROXY_HEADERS=true` (single-hop: X-Forwarded-For último valor válido + X-Real-IP validado), validados no startup (CORS_ORIGINS e TRUST_PROXY juntos em produção); comportamento do futuro proxy da VPS documentado.
5. **Lockout (Parte 4):** `app/services/lockout.py`, chaves `cifra:lock:<user_id>` (fail counter + deadline, HASH + script Lua atômico). 5 falhas → 15 min; reincidência dobra até máximo de 24 h. Sucesso reseta counter do e-mail. Identidade por user_id resolvido (existente) + fingerprint de e-mail inexistente; respostas 401 indistinguíveis (mesma mensagem/formato/latência com dummy hash já existente). Sem 500 acidental: Redis fora → login continua (política documentada), AuditEvent tenta registrar e falha silenciosa apenas para classe não-crítica.
6. **CORS (Parte 8):** `CORS_ORIGINS` lista explícita, normalização (lowercase, sem path, sem trailing slash), proibido wildcard em produção, validação no startup; allow_credentials=true (contrato bearer atual exige origens explícitas), métodos POST/GET/DELETE, headers Authorization/Content-Type.
7. **Schemas (Parte 9):** todos os request models com `extra="forbid"`; respostas já são DTOs explícitos; testes de mass assignment (user_id, is_active, session_version, password_hash rejeitados; ausentes nas respostas).
8. **Recuperação de senha (Parte 10):** confirmada nas fontes (decisões.md §Consequências 3: "envio de recuperação de senha na F1.5"; Resend opt-in; remetente de teste). `app/core/mailer.py` (protocol Mailer + NullMailer default + ResendMailer opt-in `RESEND_ENABLED`); `app/services/password_reset.py`: token 32 bytes hash-only TTL 15 min no Redis, resposta sempre 200 indistinguível, consumo único atômico, bump session_version + revoke refreshes + audit. Rate limit próprio (3/h por IP). Nenhum e-mail real em testes (NullMailer/fake).
9. **Headers web (Parte 7):** next.config headers() com CSP (script-src 'self' 'unsafe-inline' — Next.js inline bootstrap; registrado para remoção futura), HSTS (apenas com HTTPS_ENABLED=true), X-Frame-Options DENY, X-Content-Type-Options nosniff, Referrer-Policy same-origin, Permissions-Policy mínima, frame-ancestors 'none'. Testes Vitest dos headers.
10. **ZAP (Parte 11):** workflow novo com imagem `ghcr.io/zaproxy/zaproxy:stable` pinada por digest, API efêmera (compose + migração), spider+baseline contra / e /health/live, gate: High bloqueia; Medium listado no relatório (exceções só versionadas); artefato do relatório preservado; permissões mínimas; falha se zero URLs.
